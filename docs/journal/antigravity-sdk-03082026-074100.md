# Antigravity SDK Learning Journal

**Sprint:** 3
**Status:** Complete

## Objectives
- Refactor the demo into a real interactive application.
- Separate responsibilities across application layers.
- Prepare the project for ERPNext integration.

## What Changed
- Introduced interactive CLI (`while True` chat loop).
- Moved environment handling into `settings.py`.
- Moved prompt into `agent/prompts.py`.
- Centralized agent configuration in `config.py`.
- Encapsulated agent lifecycle in `agent/assistant.py`.
- Introduced a service layer and made tools thin.

## Architecture

```
User
  ↓
app.py
  ↓
Agent
  ↓
Tool
  ↓
Service
  ↓
Repository (currently in-memory)
  ↓
ERPNext (future)
```

## Lessons Learned
- Antigravity tools should expose capabilities, not business logic.
- The application entry point should orchestrate rather than implement.
- Configuration, prompts and lifecycle deserve dedicated modules.

## Sprint 3 Improvements
- Interactive CLI replaces hard-coded prompts.
- Clean separation of concerns.
- Reusable agent creation.
- Foundation for ERPNext REST integration.

## Next Sprint
Introduce a repository layer so services no longer own in-memory data.
